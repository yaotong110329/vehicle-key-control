# 車輛鑰匙控管系統：確認後規格

## 已確認決策

- 系統為離線、單機、無登入的 Windows 桌面優先網頁版，使用 IndexedDB 保存資料。
- 首次資料庫建立四把鑰匙：001、002、003、004；主畫面一律從資料庫動態產生。
- 預設勤務為：一線巡邏、二線巡邏、三線巡邏、備勤、交通整理。
- 預設人員為：張OO、曾OO、王OO、李OO。
- 快速勤務選單沒有所需選項時，可輸入一項單次自訂勤務。自訂勤務不會自動加入設定中的勤務清單。
- 快速選擇勤務與單次自訂勤務互斥：輸入自訂勤務時取消已選勤務；選擇勤務時清空自訂文字。
- 自訂勤務在使用中與歷史資料中以 `dutyId = null`、`dutyNameSnapshot = 自訂文字` 保存。
- 人員一次最多選擇一名；勤務、人員、補充三者至少有一項才可確認取用。
- 使用中鑰匙不能刪除；勤務或人員若被使用中紀錄引用也不能刪除。歷史紀錄引用不阻擋刪除。
- 使用中狀態由唯一的使用中紀錄推導，不在鑰匙資料重複儲存狀態。
- 編輯使用中紀錄可以補齊或調整勤務、人員、補充，但永遠保留原始 `checkoutAt`。
- 歸還時以單一 IndexedDB transaction 建立歷史資料並移除使用中資料；歷史按歸還時間由新到舊排序，日期篩選採取用日期。
- 歷史資料使用鍵、勤務、人員的名稱快照；後續改名或刪除皆不改寫歷史。
- 設定頁可修改頁首系統標題、總覽大標題，並上傳或移除頁首 Logo；Logo 以圖片 Data URL 保存在本機 `meta.uiSettings`。
- 第一版以本機靜態 HTTP 伺服器測試，避免 `file://` 下各瀏覽器 IndexedDB 持久性差異；不需要後端服務。
- 第一版提供 JSON 資料備份／還原；並安全處理多個頁籤的資料更新與重複取用衝突。

## 資料模型補充

`activeUsage` 與 `history` 都含可空的 `dutyId`。它有值時代表從管理清單選取；它為空而 `dutyNameSnapshot` 有值時，代表單次自訂勤務。兩種情況都只顯示一個勤務名稱。

`activeUsage.keyId` 必須有唯一索引，因此任何時刻一把鑰匙只能有一筆使用中紀錄。

## 正式需求

### 目標與範圍

系統供分隊值班人員於單一 Windows 電腦掌握車輛鑰匙去向。第一版為離線、無登入、無後端的桌面優先網頁版，使用 HTML、CSS、Vanilla JavaScript 與 IndexedDB。歷史紀錄在歸還後唯讀且不可刪除。

### 主畫面

- Header 顯示可在設定頁修改的系統標題、固定副標題、即時日期與 24 小時制時間，以及紀錄與設定入口；預設總覽大標題留白，不顯示舊版「車輛鑰匙狀態」文案。
- 鑰匙卡片依 `keys.sortOrder` 動態產生為自適應 Grid；四把鑰匙時採 2 × 2，新增或刪除後自動調整。
- 在隊卡顯示目前名稱、柔和綠色 Badge 與取用按鈕。
- 使用中卡顯示目前名稱、低飽和橘色 Badge、勤務、人員、補充、原始取用時間、編輯與無確認歸還按鈕。
- 非當日取用須連同月日顯示，避免只有時分造成誤判。

### 取用、編輯與歸還

- 取用 Modal 可選一項快速勤務或輸入一項單次自訂勤務；兩者互斥。單次自訂勤務不會加入勤務管理清單。
- 人員一次只能選一人。勤務、人員、補充至少填一項，確認按鈕才可用。
- 取用建立 `checkoutAt`。編輯帶入原資料，僅能調整勤務、人員、補充，不能變更 `checkoutAt`。
- 歸還不跳確認視窗；必須以同一個 IndexedDB transaction 寫入含 `returnAt` 的歷史紀錄後，移除使用中紀錄。成功後即時更新畫面並顯示 Toast。

### 歷史與設定

- 歷史頁按 `returnAt` 新到舊排序，日期篩選使用取用日期，並支援鑰匙篩選。
- 歷史永久保存鑰匙、勤務、人員名稱快照；任何改名或刪除均不改寫歷史。
- 鑰匙、勤務、人員均可新增、修改、刪除、上移與下移排序；名稱去除前後空白後不可空白或重複。
- 設定頁可匯出完整本機資料 JSON 備份；匯入前驗證格式、ID 與關聯，確認後以單一 transaction 整體還原，避免半套資料寫入。
- 使用中的鑰匙不可刪除。被使用中紀錄引用的勤務或人員不可刪除；歷史引用不阻擋刪除。
- 鑰匙改名立即反映目前卡片；勤務、人員改名不回寫既有使用中或歷史的名稱快照。

### 資料模型與完整性

- `keys`：`id`、`name`、`licensePlate`、`note`、`sortOrder`、`createdAt`、`updatedAt`。
- `dutyTypes`、`personnel`：`id`、`name`、`sortOrder`、`createdAt`、`updatedAt`。
- `activeUsage`：`id`、唯一 `keyId`、可空 `dutyId`、可空 `personnelId`、勤務／人員名稱快照、`note`、不可變 `checkoutAt`、`updatedAt`。
- `history`：`id`、`keyId`、`keyNameSnapshot`、勤務／人員 ID 與名稱快照、`note`、`checkoutAt`、`returnAt`。
- `meta`：schema 版本、一次性種子資料完成標記與 `uiSettings`。`uiSettings` 包含 `appTitle`、`dashboardTitle`、`logoDataUrl`；首次建立資料庫時建立 001–004、五項預設勤務與張OO、曾OO、王OO、李OO；使用者刪除資料後不可自動補回。
- 所有 ID 為 UUID，時間以 ISO 8601 儲存並用 Windows 本機時區顯示。鑰匙狀態由是否存在相同 `keyId` 的使用中紀錄推導，不重複儲存 `status`。

### UI、部署與後續

- 使用暖白背景、白卡、圓角、柔和陰影、精緻邊框與一致的 Button、Input、Modal、Toast；動畫控制在 150–250ms，不使用過度漸層或玻璃擬態。
- 不載入網路字型或其他外部資源；Modal 必須具備焦點管理與 Esc 關閉。
- 第一版固定在同一 Windows 使用者帳戶的 Microsoft Edge 與固定 `http://localhost` 位址及連接埠運行。Chrome 可用於開發測試，但其 IndexedDB 資料與 Edge、其他設定檔及其他連接埠完全不共用；不得使用 InPrivate／無痕模式或清除網站資料。
- 第一版以跨頁籤更新與 `activeUsage.keyId` 唯一索引防止重複取用，並提供 JSON 備份／還原；Windows 交付採 Tauri 2 NSIS current-user 安裝、離線 WebView2 與啟動最大化。
